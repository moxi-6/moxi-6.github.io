# 逻辑综合：从 RTL 到网表

<div class="page-meta">E5 · 02　状态：学习中</div>

本页记录逻辑综合的基础概念和流程。内容会随着实践继续补充。

## 逻辑综合的目标

RTL 代码描述电路功能和结构，RTL 仿真通过软件验证行为。真正制造芯片时，还需要把 RTL 转换为具体工艺能够实现的逻辑单元和连接关系。

```text
RTL 代码
  ↓ 逻辑综合
标准单元网表
  ↓ 物理设计
GDSII 版图
  ↓
晶圆厂制造
```

最核心的关系是：

```text
综合器输入：RTL 代码
综合器输出：标准单元网表
```

## 关键概念

| 概念 | 含义 |
|---|---|
| GDSII | 描述版图中器件位置与走线位置的文件格式 |
| PDK | 晶圆厂提供的工艺设计套件 |
| 标准单元 | 特定工艺支持的基础逻辑单元 |
| 逻辑综合 | 把 RTL 描述转换成标准单元实现 |
| 网表 | 记录使用的单元以及单元之间的连接关系 |

## 基本流程

1. **Parsing**：读取并解析 HDL 源文件；
2. **Elaboration**：展开参数、模块实例和层次结构；
3. **Coarse-grain synthesis**：把高层运算转换成较粗粒度的逻辑结构；
4. **Fine-grain synthesis**：继续分解和优化为基本逻辑；
5. **Technology mapping**：映射到目标工艺的标准单元；
6. **Netlist / Report**：生成网表和面积、时序等报告。

## 当前理解

- RTL 不是最终电路，而是综合器的输入描述；
- 仿真正确不代表一定能够综合，也不代表综合结果最优；
- 综合工具必须结合目标工艺库，才能生成可用于后续流程的网表；
- 编码风格会影响综合器能否正确推断电路结构。
